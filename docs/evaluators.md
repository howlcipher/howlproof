# Evaluators

Generated by `scripts/build_evaluator_docs.py` from the registry. Do not edit by
hand; `tests/test_docs.py` fails when this file and the code disagree.

Every evaluator probes the tooling it needs before running, reports
`NOT_APPLICABLE` when the artifact has no such surface, `UNAVAILABLE` when the
tooling is absent, and attaches to each result a statement of what the check does
**not** establish.

## Profiles

| Profile | Evaluators | Description |
| --- | --- | --- |
| `ai` | 2 | Indirect prompt injection and structured-response handling. NOT_APPLICABLE unless the artifact declares an AI entry point. |
| `api` | 4 | A running HTTP surface, its refusals and its behaviour under malformed input. |
| `code` | 9 | The artifact own build, lint, type and test gates, reported honestly. |
| `default` | 27 | A broad pass over whatever surfaces the artifact declares. Evaluators that find no surface report NOT_APPLICABLE rather than passing vacuously. |
| `documentation` | 4 | Absolute claims, files documented as synchronised, and operator-facing guards. |
| `go` | 3 | Go formatting, vet and tests. |
| `python` | 7 | Python packaging, typing, linting and tests in a freshly provisioned environment. |
| `release` | 3 | Version agreement and the supply chain that publishes the artifact. |
| `reliability` | 4 | Failure, restart and corruption behaviour. The service-disrupting checks run last so they cannot disturb the evidence gathered before them. |
| `security` | 7 | The defensive security adversary. Bounded, authorised probes against an artifact the operator owns; it ships no general exploitation tooling. |
| `web` | 5 | The published interface, covering references, discovery metadata and rendered behaviour at the declared widths. |

A single evaluator id is accepted anywhere a profile name is, so one check can be re-run in isolation:

```bash
howlproof evaluate . --profile markup.escaping
```
